Everything you need to update products, prices, and the catalog — safely. Read the two laws once, then use the walkthroughs. Every step below is the LIVE dashboard: vendors.paddle.com, top of screen says "You're in Live" — never sandbox.

First, the two lawsBreak either and checkout breaks

Law 1 — Price IDs are welded into our code. The site's checkout opens Paddle with three hardcoded pri_… IDs. If a price is archived or replaced without syncing the code first, students click Subscribe and hit a dead price. Code first, archive second — always in that order.
Law 2 — The catalog is what students are charged; the site is what they're told. After any catalog change, the site copy (paywall cards, pricing page) must match. A mismatch here is also a verification red flag for Paddle.

Walkthrough AEdit product info — name, description, icon

  1. Log in at vendors.paddle.com. Confirm "You're in Live" at the top.
  2. Go to Catalog → Products and click the product you want to edit.
  3. Edit the fields: Name (e.g., "Anastomosis.MD — Monthly" when we rebrand), Description (shown at checkout and on customer documents), and Image / icon URL.
  4. For the icon, paste the mark's raw GitHub URL:
    https://raw.githubusercontent.com/alihoury003/Anastomosis.MD/main/mark-dark-512.png
    Open that URL in a tab first — if the mark looks like a ghost on white, use mark-light-512.png at the same path. Paddle doesn't host images: it needs a public HTTPS URL, square 1:1.
  5. Save. Zero code impact — live on the next checkout. This is the safe playground: rename and re-describe freely.

Walkthrough BChange a price amount — the careful one

You cannot edit an amount in place. A new amount = a new price = a new pri_ ID. This is by design in Paddle Billing. The sequence below keeps checkout alive the whole way through.
  1. Tell me the new amount(s) first. I prepare the code change (the PADDLE_PRICES constants + plan labels) so it's ready to deploy the moment you have the new IDs.
  2. In Paddle: Catalog → Products → open the product → scroll to the Prices section → New price.
  3. Set the new amount, and match the same billing period/interval as the price you're replacing (monthly → monthly; the 6-month plan keeps its 6-month cycle; annual → annual). Save.
  4. Click the ⋯ menu next to the new price → Copy price ID.
  5. Send me the ID. I paste it into PADDLE_PRICES, you deploy dashboard.html to main (hub download → GitHub upload).
  6. Only now archive the old price: ⋯ menu on the old price → Archive. Archiving stops new sales of it — it never touches existing subscribers (they keep the price they signed up at).
If you archive before the code swap, every Subscribe click in between hits a dead price. Order is everything.

Walkthrough CAdd a new plan (e.g., replacing "Coming soon")

  1. Catalog → Products → New product. Name it, tax category Standard, save.
  2. On the product page: Prices → New price → amount + billing period → save.
  3. Copy the new pri_ ID (⋯ menu → Copy price ID).
  4. Send me the ID — I wire it into the checkout constants, the paywall plan cards, the labels, and pricing.html. You deploy. One email, one deploy, done.

Verifying it workedNo test cards in live — that's what sandbox is for

  1. The paywall is your live preview: log in to the site → Upgrade → the plan cards load real prices straight from Paddle. If they show your new amounts, the catalog and the wiring are live.
  2. Full checkout rehearsal: ask Charlie's team for their recommended test path on a live account (they do this for merchants constantly). Don't invent workarounds with real cards.

Do not touch (for now)While account verification is in flight

  1. Business details & payout settings — changing identity-adjacent fields mid-verification resets the review.
  2. Notification destinations / webhooks — never delete or recreate; that rotates the signing secret.
  3. Products with history — archive, never delete.
  4. The sandbox world — it's a separate universe; we're not using it yet.
