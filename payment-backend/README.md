# Payment integration — staged work, not ready for deployment

This directory contains an **incomplete, disabled** Appwrite/Paddle integration under development. Do not upload or deploy it, connect it to Paddle, set its feature flags, or accept live payments based on it. It does not replace the existing live checkout and does not secure the publicly readable question bank.

## Implemented and locally tested

- `src/checkout.mjs` and `checkout-session.cjs`: obtain an authenticated Appwrite identity through a JWT verified against Appwrite, then produce a server-signed checkout binding containing user, price, environment and explicit renewal choice. The browser cannot choose a different user ID by altering metadata. The session endpoint remains disabled by default.
- `src/main.mjs`, `paddle-webhook.cjs` and `appwrite-event-store.cjs`: verify Paddle's HMAC signature over the exact body, enforce timestamp tolerance and private, duplicate-aware event storage. Storage errors do not return success. The webhook endpoint remains disabled by default.
- `src/worker.mjs`, `process-queue.cjs`, `process-event.cjs`, `appwrite-queue-store.cjs` and `appwrite-mapping-store.cjs`: a staged scheduled worker reads queued events, checks their hashes, queries current Paddle subscription data, validates signed bindings, stores private immutable mappings, and attempts to schedule end-of-period cancellation for a nonrenewing choice. Failures leave events for retry. The worker remains disabled by default.
- `src/access.mjs`, `entitlement-service.cjs`, `entitlement-policy.cjs` and `paddle-client.cjs`: an authenticated, conservative access check against server-side mappings, current Paddle subscription data, and all adjustment pages. The check does not trust user-editable preferences. It is disabled by default, not integrated into the dashboard, and does not grant access or protect questions by itself.
- `tests/payment-flow-mocked-e2e.test.cjs` connects the staged checkout, webhook, private event store, worker, Paddle adapter, mapping and access check to a fake in-memory service. Additional tests exercise invalid signatures, incorrect identities, retries, store conflicts, API outages, adjustments and cancellation. Install the pinned server SDK with `npm ci --prefix payment-backend --ignore-scripts`, then run `node --test tests/*.test.cjs`. **All mocks only**: no actual Paddle payment, Appwrite Function execution, browser checkout, scheduler or collection permissions have been tested.

### Staged question gateway (still disabled)

- `question-access.cjs`, `question-routes.cjs` and `src/questions.mjs` implement candidate authenticated delivery for one question or a block of up to 20. They return sanitized metadata, use only server-verified subscription state, and require private per-user usage storage. Previously granted questions have a separate review route.
- `appwrite-questions.cjs` and `appwrite-usage-store.cjs` use the pinned Node SDK and Appwrite transactions; `browser-gateway.mjs` and `dashboard-bridge.mjs` provide staged adapters for the dashboard. **The real dashboard does not import or call these adapters.** The protected database table, usage table, Appwrite Function and user migration have not been provisioned.
- The candidate quota counts each newly **delivered** distinct question, not each first answer as the current dashboard does; previously delivered questions remain reviewable. It uses UTC calendar days. These are user-visible behavioral differences, not an approved product change. A delivered but unanswered item consumes quota. Past questions delivered while subscribed are not automatically granted for free review after expiry. Existing account history and trial states cannot safely be inferred from client-editable preferences without a reviewed migration policy.
- Tests use an in-memory serialized fake for concurrency and a mocked SDK transport; they **do not prove** Appwrite transaction isolation, correct schema/indexes, real-world performance, free-plan limits, data migration or browser/exam behavior. The function is disabled by default and requires an installed server SDK. Never remove `Any → Read` or enable this until the actual migration and end-to-end tests are complete; keep the importer admin explicitly authorized, including read access, when public read is eventually removed.

The live catalog and site were not changed. No server API keys, signing secrets or real customer data are included. The archived event payloads would contain customer data; before enabling, provision private collections with no client permissions and review retention, encryption and least-privilege access. The archive rejects event bodies over 32 KB; assess the real event-size limit before use. The Appwrite event store schema and required indexes are not yet provisioned or tested.

## Blocking work before any launch

1. **Question access and free-tier redesign:** The live dashboard still downloads the whole bank directly and the questions table remains publicly readable. The candidate gateway above is not wired into the dashboard and its delivery-based quota semantics differ from the current answer-based behavior. Finish a concurrency-safe, genuinely compatible integration and reviewed migration for existing progress and trial histories; preserve importer access and the existing exam interface. Remove public read only after real end-to-end tests. Do not silently change trial terms or make free users lose progress.
2. **Billing guarantee:** Existing live prices recur, whereas the site promises auto-renew is not the default. The staged worker's attempt to cancel recurring subscriptions is **not a reliable guarantee** during prolonged outages or missed events, and changing a user's renewal choice later is not implemented. Design and test a reliable nonrenewing default (potentially separate one-time prices) and explicit opt-in renewal before opening checkout. Do not change, archive or recreate any live price without synchronizing the website and getting approval.
3. **Frontend integration:** The live dashboard still opens checkout directly, trusts client-editable subscription preferences and does not use these endpoints. No dashboard patch is shipped here. The default-link page at `/checkout.html` is deployed but its real transaction and payment-method-update flows have not been validated.
4. **Operational safety:** Implement durable scheduled-worker reconciliation for missed and out-of-order events, monitoring/alerts and manual-review tooling, cancellation and refund/chargeback workflows, choice changes, recovery from errors, permissions, schema/index provisioning and resource-limit checks. The current worker is not configured or deployed. With expired or missing event deliveries, a subscription can be billed despite a no-renewal selection; do not rely on this worker to prevent that.
5. **Real testing and deployment:** Review security and legal copy; test real Appwrite APIs, all authorization paths and Paddle sandbox events, checkout, user binding, duplicate/out-of-order events, refunds, cancellation, paid/free access, importer, concurrency and outages. Verify the public payment-link page using real sandbox transaction and payment-method-update links. Then plan any authorized live test. Ali must configure Appwrite/Paddle and enter secrets privately; the agent does not have access to those accounts.

No test result here proves production readiness. No production setting or file is changed by this directory.
