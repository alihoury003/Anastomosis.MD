# Paddle backend work in progress — do not deploy

`paddle-webhook.cjs` is an unconnected, dependency-free foundation for authenticating Paddle webhook events. It validates HMAC-SHA256 against the exact raw bytes and timestamp, uses timing-safe comparisons, handles repeated signatures, checks basic event shape, and accepts an injected durable idempotent archive. It fails closed on bad signatures or storage failures. It does not use or contain a production secret. Tests: `node --test tests/paddle-webhook.test.cjs`.

**This is not a payment integration.** There is no deployed endpoint, archive implementation, event processor, trusted subscription-to-user mapping, server-side entitlements, protected question delivery, free-tier quota enforcement, renewal choice, retry reconciliation or real Paddle sandbox test. Do not deploy it or point notifications at it. In particular, accepting and archiving a webhook without a working durable processor would leave customers without access. No live Paddle, Appwrite or site settings were changed by this work.

Before production: verify against Paddle's current SDK and simulator, create a private durable event store with replay/idempotency and reconciliation, authenticate/bind checkout sessions to Appwrite users server-side, build least-privilege entitlements and question access without breaking the free tier or importer, resolve the site's no-default-renewal promise, implement robust delivery of paid-access updates and revocations, cover out-of-order/repeated/missing events and provider outages, and conduct end-to-end sandbox and authorized live checks. Confirm all permissions with actual project configuration before changing them.
